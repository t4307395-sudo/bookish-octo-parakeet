# نظام الاختبار التنافسي (Live)

مبني على: Cloudflare Pages (استضافة الصفحات الثابتة + الـ Functions) + Cloudflare D1 (قاعدة بيانات SQL مجانية).

## هيكل المشروع
- `public/` → الصفحات (index.html للإنشاء، play.html للحل، results.html للنتائج)
- `functions/api/...` → الـ API (Cloudflare Pages Functions، بتشتغل بدون سيرفر منفصل)
- `schema.sql` → تعريف الجداول في قاعدة البيانات

## خطوات الرفع والتشغيل

### 1) ارفع المشروع على GitHub
اعمل ريبو جديد وارفعله محتويات المجلد ده كله زي ما هي.

### 2) اعمل قاعدة بيانات D1
من موقع Cloudflare (dash.cloudflare.com):
1. روح **Workers & Pages → D1**
2. اعمل **Create database** وسمّيها مثلاً `quiz-db`
3. افتحها → تبويب **Console** → الصق محتوى ملف `schema.sql` كامل ودوس Execute
   (أو من الترمينال لو معاك wrangler: `wrangler d1 execute quiz-db --file=./schema.sql`)

### 3) اربط الريبو بـ Cloudflare Pages
1. من Cloudflare Dashboard → **Workers & Pages → Create → Pages → Connect to Git**
2. اختار الريبو بتاعك
3. Build settings: سيبها فاضية (مفيش build command، المشروع static أصلاً)
   - **Build output directory:** `public`
4. دوس Deploy

### 4) اربط قاعدة البيانات بالمشروع (مهم جداً)
1. روح لمشروع الـ Pages بعد ما يتعمل deploy
2. **Settings → Functions → D1 database bindings**
3. دوس Add binding:
   - **Variable name:** `DB` (لازم يكون بالظبط `DB` لأن الكود بيستخدم `env.DB`)
   - **D1 database:** اختار `quiz-db`
4. احفظ، وبعدين اعمل **Retry deployment** (أو أي كوميت جديد) عشان الـ binding يفعل

### 5) جرّبه
افتح رابط المشروع (هيكون شكله `https://اسم-المشروع.pages.dev`)
- `/index.html` → عشان تعمل اختبار جديد وتاخد رابط الدعوة
- الرابط اللي هيتطلعلك (`/play.html?quiz=الكود`) → ابعته للمتنافسين
- `/results.html?quiz=الكود` → النتائج الحية لحظة بلحظة

## تسجيل الدخول (طلاب + أدمن)
- `/register.html` و `/login.html` لعمل حساب/دخول الطلاب.
- عشان تبقى أنت الأدمن: من Cloudflare Dashboard → مشروع الـ Pages → **Settings → Environment variables**،
  ضيف متغير باسم `ADMIN_EMAIL` وقيمته إيميلك بالظبط. أي حساب يتسجل بنفس الإيميل ده هيتحول تلقائياً لأدمن.
  لازم تضيفه *قبل* ما تعمل تسجيل بإيميلك، وبعد أي تغيير لازم Retry deployment.
- بعد التسجيل كأدمن، هتقدر تدخل `/admin.html` وترفع أسئلة بصيغة JSON مباشرة (بدل الدخول على D1 Console يدوي).

### شكل ملف/نص الأسئلة في `/admin.html`
```json
{
  "category": "رياضيات",
  "questions": [
    {"text": "2+2؟", "option_a": "3", "option_b": "4", "option_c": "5", "option_d": "6", "correct_option": "b"}
  ]
}
```
لو حددت `category`، الأسئلة بتتخزن في بنك منفصل، وتقدر تختاره من قائمة الفئة عند إنشاء اختبار جديد.

### ترقية قاعدة بيانات موجودة
إذا كانت لديك قاعدة D1 قديمة، شغّل الملف `migrations/001_platform_v4.sql` مرة واحدة وبالترتيب من D1 Console أو Wrangler، ثم أعد النشر. لا تعِد تشغيل ملف `schema.sql` كاملًا على قاعدة موجودة. أما قاعدة البيانات الجديدة، فملف `schema.sql` يحتوي على كل الأعمدة والجداول المطلوبة ويمكن تشغيله بأمان أكثر من مرة.

## طريقة إضافة الأسئلة من جوجل شيت
رتّب الأعمدة في الشيت بالترتيب ده:

| السؤال | اختيار أ | اختيار ب | اختيار ج | اختيار د | الإجابة الصح |
|---|---|---|---|---|---|
| عاصمة مصر؟ | القاهرة | الإسكندرية | الجيزة | أسوان | a |

> ⚠️ تصحيح: النسخة الحالية **مفيهاش** حقل "لصق الأسئلة" مباشر في `index.html` -
> الطريقة الوحيدة الفعلية لإضافة أسئلة للبنك هي عبر `/admin.html` (تسجيل دخول
> كأدمن، وبعدين رفع صيغة JSON). لو عندك بيانات في جوجل شيت زي الجدول فوق،
> حوّلها لـ JSON بالشكل ده الأول (تقدر تستخدم أي أداة تحويل أو حتى تطلب من
> Claude/ChatGPT يحولّها لك) وبعدين الصقها في `admin.html`:
> ```json
> {
>   "category": "جغرافيا",
>   "questions": [
>     {"text": "عاصمة مصر؟", "option_a": "القاهرة", "option_b": "الإسكندرية",
>      "option_c": "الجيزة", "option_d": "أسوان", "correct_option": "a"}
>   ]
> }
> ```
> ملحوظة: لازم تكون الإجابة الصح بحرف واحد صغير (a, b, c, أو d) مطابق لترتيب الاختيارات.

### فصل بنك الامتحان عن بنك التدريب (exam_only)
في `admin.html` فيه خانة اختيار "أسئلة امتحان فقط". لو حددتها، الأسئلة دي
بتتحفظ في البنك لكن **بتتخفى من التدريب الحر وسؤال اليوم** (اللي بيوريا
الإجابة الصح فورًا للطالب). كده تقدر تعمل بنكين منفصلين لنفس الفئة: بنك
عام للتدريب يشوفه الطلاب براحتهم، وبنك "امتحان" تسحب منه الاختبارات
التنافسية الحقيقية بس - بدون ما الطالب يكون شافه قبل كده في التدريب.

## ملاحظات على السلوك الحالي
- **إنشاء اختبار محتاج تسجيل دخول** (من v4): أي حساب مسجل يقدر ينشئ اختبار،
  وبيتسجل كـ"مالك" الاختبار عشان تقدر ترجع تشوف كل اختباراتك من صفحة
  `/my-quizzes.html` بدل ما تحتفظ بكل رابط لوحده.
- **الدرجة** = عدد الإجابات الصحيحة فقط (مفيش بونص سرعة). لو عايز بونص سرعة أو ترتيب بالوقت عند تساوي الدرجات قولّي أظبطه.
- **المؤقت** واحد للاختبار كله (مش لكل سؤال لوحده) وبيبدأ لحظة ما اللاعب يدوس "ابدأ".
- **صفحة النتائج** بتتحدث كل 3 ثواني لحد ما كل المشاركين يخلصوا (مفيش حاجة يدوية)، وفيها زرار تصدير CSV وزرار تحليل نسبة الإجابة الصح لكل سؤال.
- أي حد معاه رابط `play.html?quiz=الكود` يقدر يشترك، فخليك مركز إنك تبعت الرابط للمتنافسين بس.
- الاختبار مفتوح لأي عدد لاعبين (مش لازم يبقوا اتنين بالظبط) — لو عايزها مضبوطة على اتنين بس قولّي أضيف الشرط ده.
- **Rate limiting** (من v4): بعد 8 محاولات دخول غلط على نفس الإيميل خلال 15 دقيقة، أو 10 حسابات جديدة من نفس الـ IP خلال ساعة، النظام بيرفض المحاولة لحد ما الوقت يعدي.

## تعديلات ممكنة لو حبيت
- بونص على السرعة في حساب الدرجة
- قفل الاختبار تلقائي بعد ما عدد معين من اللاعبين يخلصوا
- استيراد الأسئلة مباشرة من رابط جوجل شيت المنشور (Google Sheets API) بدل النسخ اليدوي
- صفحة أدمن لعرض كل الاختبارات القديمة ونتائجها

## اللي لسه محتاج شغل (Roadmap للمنصة)
> ملحوظة: القايمة القديمة هنا كانت فيها بنود اتعملت بالفعل في نسخ لاحقة (لوحة
> الصدارة، اختيار الفئة، Rate limiting) ومحدش حدّثها - دي القايمة المحدّثة
> الفعلية اعتبارًا من v4. راجع `ROADMAP-v4.md` لتفاصيل كل حاجة اتضافت.
- تعديل مباشر لمحتوى السؤال من شاشة بلاغات الأدمن (دلوقتي التعديل بس من رفع JSON تاني).
- صعوبة الأسئلة (سهل/متوسط/صعب) وسحب متوازن منها عند إنشاء اختبار.
- أنواع أسئلة تانية غير اختيار من متعدد (صح/خطأ، إجابة مقالية قصيرة تحتاج تصحيح يدوي).
- كشف تبديل التبويب/الخروج من صفحة الاختبار كمؤشر غش محتمل.
